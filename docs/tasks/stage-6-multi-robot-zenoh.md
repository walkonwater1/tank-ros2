## S6-01 · 命名空间与 TF 隔离

| 状态 | 依赖 | 硬件 | 预计 |
|---|---|---|---|
| TODO | S5-05 | 否 | 0.5 天 |

**目标**：多机器人话题和坐标系不串。

**步骤**
1. 每个机器人一个命名空间：`/robot1/*`、`/robot2/*`。
2. launch 中使用 `PushRosNamespace` 或 `namespace` 参数。
3. `robot_state_publisher` 放进命名空间，frame 加前缀：
   `robot1/odom → robot1/base_link`。
4. 检查 `/tf` 与 `/tf_static` 是否被正确隔离。
5. 写一份多机 launch 模板。

**验收**
- [ ] 两个命名空间可同时启动
- [ ] `/robot1/cmd_vel` 不影响 robot2
- [ ] TF 树互不干扰
- [ ] RViz 可分别显示

## S6-04 · 切换到 rmw_zenoh

| 状态 | 依赖 | 硬件 | 预计 |
|---|---|---|---|
| TODO | S6-02 | 是 | 1 天 |

**目标**：同一套 ROS2 代码跑在 Zenoh 上，理解差异。

**步骤**
1. 安装 `rmw_zenoh_cpp`（包名随发行版变化）。
2. 设置：
   ```bash
   export RMW_IMPLEMENTATION=rmw_zenoh_cpp
   ```
3. 启动 Zenoh 路由（`rmw_zenohd` 或 `zenohd`）。
4. 跑 talker/listener、`/cmd_vel`、TF。
5. 记录与 DDS 的差异：发现、延迟、CPU、断线重连。
6. 注意：所有节点使用同一个 RMW，混用需桥接。

**验收**
- [ ] 单机通信正常
- [ ] 跨机通信正常
- [ ] 服务/动作可用
- [ ] 有与 DDS 的对比记录

**风险**：不同发行版默认 RMW 不同；QoS 映射差异；工具兼容性。

## S6-05 · Zenoh 路由与安全

| 状态 | 依赖 | 硬件 | 预计 |
|---|---|---|---|
| TODO | S6-04 | 是 | 1 天 |

**目标**：搭一个可扩展的路由拓扑，并做基本安全配置。

**步骤**
1. 部署 `zenohd`（RK3588 或 H618）。
2. 配置 TCP endpoint、gossip、scouting。
3. 多台机器人连到路由器。
4. 配置 TLS/mTLS（跨公网时必需）。
5. 配置 ACL，限制可读写 key。
6. 测试断线重连和路由切换。

**验收**
- [ ] 路由器拓扑稳定
- [ ] 断线自动重连
- [ ] 公网暴露时有 TLS + ACL
- [ ] 有配置文件版本化

**风险**：默认配置暴露到公网；版本不兼容；NAT/防火墙。

## S6-07 · 可选：bridge-dds / zenoh-pico

| 状态 | 依赖 | 硬件 | 预计 |
|---|---|---|---|
| TODO | S6-06 | 是 | 2 天+ |

**目标**：探索混合组网和 MCU 直连。

**方向**
- `zenoh-bridge-dds`：让现有 DDS 网络与 Zenoh 互通。
- `zenoh-pico`：ESP32 直接说 Zenoh，减少一层桥接。

**步骤**
1. 选一个方向，明确要解决的问题。
2. 搭最小验证：一条消息从端到端。
3. 记录序列化、key 约定、QoS 差异。
4. 评估是否值得进入主线。

**验收**
- [ ] 最小链路打通
- [ ] 有性能/复杂度评估
- [ ] 结论明确（采用/搁置）

**风险**：ROS2 消息 CDR 序列化、key 约定、版本兼容，属于深水区。
