# 串口控制协议 v1

> 对应任务：S1-02  
> 链路：命令服务器（ROS2 `tank_bridge`）→ Wi-Fi/网络 → ESP32-S3（Yuyi A2 V1）
> 状态：设计稿，待实车联调后修订

---

## 1. 物理层

Demo 的正式控制链路为命令服务器到 ESP32-S3 的 Wi-Fi 网络。以下 UART 参数用于固件调试，或在命令服务器与 ESP32 近距离直连时作为本地桥接方案，不代表 H618 必须与小车直连。

| 项 | 值 |
|---|---|
| ESP32 控制接口 | Wi-Fi 网络控制；底层 UART1 可作为固件调试或本地桥接接口 |
| ESP32 TX | `GPIO8` → 接命令服务器 RX（本地 UART 桥接时） |
| ESP32 RX | `GPIO10` ← 接命令服务器 TX（本地 UART 桥接时） |
| 电平 | **3.3V TTL**，双方必须共地；不要接 RS232/5V |
| 波特率 | 921600（仅 UART1 调试/桥接时适用） |
| 数据位 / 校验 / 停止位 | 8 / N / 1 |
| 流控 | 无 |
| 线序 | TX→RX、RX→TX、GND→GND；VCC 不接（各自供电） |

> 备选方案：用 UART0（TX=43 / RX=44）时，必须先把 ESP32 console 从 UART0 迁到 USB Serial/JTAG，否则日志会和控制帧互相干扰。本版本**不改 console**，优先用 UART1。

> GPIO8 / GPIO10 在厂商 `config.h` 中未占用，排针有引出；上电前用万用表确认 P1 排针脚序。

## 2. 帧格式

单行 ASCII，以 `\n` 结尾（兼容 `\r\n`）：

```
W,<left>,<right>\n
```

| 字段 | 类型 | 范围 | 含义 |
|---|---|---|---|
| `W` | 字符 | 固定 | 轮子速度命令（Wheel） |
| `left` | 十进制整数 | −100 ~ 100 | 左履带占空比，正值前进 |
| `right` | 十进制整数 | −100 ~ 100 | 右履带占空比，正值前进 |

示例：

```
W,100,100\n    左右满速前进
W,-60,-60\n    左右 60% 后退
W,-80,80\n     原地左转（左退右进）
W,0,0\n        停车
```

**约定**

- 超范围的数值由 ESP32 侧 clamp 到 `[−100, 100]`，不判为非法帧。
- 无法解析的行直接丢弃并打警告日志，不影响上一帧的运动状态。
- 一行超过 31 字节视为噪声，清空缓冲区重新收取。
- v1 无 ACK、无 CRC：20Hz × 约 14 字节 ≈ 280 B/s，载荷极低；用 `minicom`/`screen` 可直接观察。若 30 分钟稳定性测试出现乱帧，再考虑加校验。

## 3. 时序与看门狗

| 项 | 值 | 位置 |
|---|---|---|
| 主机下发频率 | 20 Hz（50 ms/帧） | `tank_bridge` 的 `publish_rate` 参数 |
| 看门狗超时 | 500 ms | **ESP32 侧** |
| 主机侧超时 | 500 ms | `tank_bridge` 的 `timeout` 参数 |

双层保护：

1. 命令服务器上的 `/cmd_vel` 断流 500ms → `tank_bridge` 发 `W,0,0`。
2. ESP32 收到过至少一帧合法 `W` 后，若 500ms 内没有新帧 → 自动 `W,0,0` 并记日志。即使主机宕机、串口断开，小车也会停。

> 第 2 条是安全底线：任何运动链路都必须有 ESP32 本地看门狗，不能依赖服务器、H618 或网络。

H618 不在 `W` 命令链路中。它可以订阅状态和传感器数据并上报服务器，但不能绕过命令服务器直接控制底盘。

## 4. 差速解算（主机侧）

`tank_bridge` 收到 `/cmd_vel` 的 `linear.x = v`、`angular.z = w` 后：

\[
left = 100 \cdot \mathrm{clamp}\left(\frac{v - wL/2}{v_{max}}, -1, 1\right), \qquad
right = 100 \cdot \mathrm{clamp}\left(\frac{v + wL/2}{v_{max}}, -1, 1\right)
\]

其中 \(L\) 为轮距（`wheel_separation`，默认 0.20 m），\(v_{max}\) 为满占空比对应线速度（`max_linear`，默认 0.40 m/s）。

符号约定：

- `v > 0` → 前进，`w > 0` → 左转（ROS 右手系，逆时针为正）。
- 左轮 = `v − wL/2`，右轮 = `v + wL/2`，与 `spark_bot_motion_control` 的 `left = base + turn` 语义**不同**，不要混用。

参数初值均为估测，实车架空轮子后标定：

| 参数 | 初值 | 标定方法 |
|---|---|---|
| `wheel_separation` | 0.20 m | 量左右履带中心距 |
| `max_linear` | 0.40 m/s | 满速跑 1m 计时 |
| `max_angular` | 1.50 rad/s | 原地转一圈计时 |

若方向反了，优先改 `tank_bridge.yaml` 的参数符号；确认是电机线序问题再交换插头。

## 5. 状态回传（可选，阶段 1 扩展）

预留但 v1 不实现：

```
S,<left>,<right>,<battery_mv>\n
```

由 ESP32 以 5Hz 上报实际左右轮设定值和电池电压，供 `tank_bridge` 发布 `/diagnostics`。等阶段 4 加入编码器后，把 `left/right` 换成实测轮速更有意义。
